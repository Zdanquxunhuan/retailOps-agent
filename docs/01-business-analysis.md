# 01 业务分析与现有系统调研

## 五场景能力矩阵

以下入口方向来自任务书，接口路径、表名、错误码及补推能力尚未通过源码确认。

| 场景 | 入口与独立策略 | 关键证据 | 必须确认的差异 |
|---|---|---|---|
| 美团销售 | 平台回调；MeituanSaleDiagnosis | 回调、处理记录、POS 状态、平台搜索 | 5 天窗口、分页、回调重试、本地补推幂等 |
| 美团退货 | 平台回调；MeituanReturnDiagnosis | 退货接收、原单关联、POS 退货单 | 退货单号/原单号、多次部分退货、重新获取能力 |
| 京东销售 | 平台回调；JdSaleDiagnosis | 京东回调、数据库、POS | 独立状态码、签名与门店映射、补推协议 |
| 京东退货 | 平台回调；JdReturnDiagnosis | 退货处理、原销售状态、POS | 售后单与退货单关系、重复事件、数量金额校验 |
| 京东税率补充 | 本地任务主动拉取；JdTaxDiagnosis | 任务触发、运行实例、锁、游标、分页响应、转换和 POS | 批次范围、补充版本、断点恢复、单单重放能力 |

平台可查订单不意味着可重新构造回调；不能把搜索响应直接作为补推请求。退货能力和京东接口窗口分别标记 UNKNOWN，源码核验后再启用。税率补充不使用“有没有收到平台回调”作为诊断起点。

## 身份与时间

业务定位键由租户（如适用）、环境、平台、业务类型、门店、业务单号组成；原销售单号不能替代退货事件标识。税率补充还需核实业务版本/批次标识。订单号作为字符串处理，保留前导零。

订单时间是独立字段，不从示例单号 MT202611090001 推断。用户未给时间时，先以只读本地查询补充；无法可靠得到时追问。自然语言相对时间按 Asia/Shanghai 解释并要求用户确认有歧义的日期。数据库存 UTC，同时保存原始时区与平台时间。

## 状态语义

不能用一个 SUCCESS 覆盖整个链路。报告分别列出 transportStatus、posReceiptStatus、posBusinessStatus、postingStatus，每项含 source、observedAt 与 UNKNOWN。HTTP 200 仅表示通信结果；POS 业务错误码仍可能失败；门店过账是另一个业务环节。

若 POS 明确接收且业务处理完成、未过账，输出“订单已经推送到 POS，仍需门店完成过账”。仅有接收回执时只能说“POS 已接收，业务处理与过账状态尚待核验”。

## 源码资料清单（按优先级）

| 优先级 | 提供资料 | 用于回答 |
|---|---|---|
| P0 | 美团项目 pom、模块目录、回调 Controller、销售 Service、DTO、DAO/Mapper、POS Client、重试代码 | 实际处理链路、事务边界、异常吞掉位置 |
| P0 | 本地订单与推送记录表 DDL、索引、状态枚举、脱敏样例 | 是否存在唯一键、状态查询可信度、重复检测 |
| P0 | 平台搜索、本地补推、POS 查询协议及成功/失败响应 | 能否补查、回放、核验；幂等键与状态映射 |
| P0 | 一笔成功、一笔失败、一笔超时订单的脱敏完整日志 | 多行堆栈、关联字段、时间偏移、回执证据 |
| P0 | 美团服务实例清单、部署方式、日志目录/轮转/保留期、网络边界说明 | 跨服务器查询完整性与接入成本 |
| P1 | 美团退货 Controller/Service/DTO、原单关联与补推代码 | 是否支持多次部分退货、取回退货数据 |
| P1 | 京东销售与退货同等资料、鉴权和门店映射说明 | 独立适配器规则 |
| P1 | 税率补充调度入口、Cron/调度平台、游标/任务锁/分页与重跑代码 | 漏跑、拉取为空、部分成功、批次恢复 |
| P2 | 运维 SOP、错误码说明、历史工单及业务负责人确认结果 | RAG 与黄金评测集 |

可以分批提供，第一批仅美团销售即可。删除账号、密码、Token、客户姓名、电话、地址；用一致的伪造 ID 替换订单与门店标识以保持关联。不需要提供 SSH 或生产访问权限。

## 调研交付与放行条件

读源码后形成“接口能力登记表”：系统/业务类型、接口版本、请求响应、权限、超时、限流、查询一致性、幂等保证、验证负责人、测试证据。能力值只允许 VERIFIED/UNSUPPORTED/UNKNOWN，UNKNOWN 默认关闭副作用工具。

每条链路至少完成一次测试环境追踪，从平台输入一直到 POS 查询；业务负责人确认状态映射后才开启该场景。日志找不到、平台搜索为空、任务没有合格数据都须单独保留为观察事实，不能直接归因为平台故障。
