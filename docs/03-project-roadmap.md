## 可独立推进的工作

源码尚缺时可以设计 DTO、Mock 契约、状态机与评估数据格式；真正业务字段映射、平台签名、幂等保证、退货规则、税率游标不得凭空实现。此次按用户要求在设计后停止，以上不是立即开始编码的授权。

## MVP 演示验收

输入一笔美团销售问题，系统能追问订单时间，显示跨两实例的日志覆盖，本地与平台查询证据，POS 分层状态及带引用的结论。演示分别覆盖：已成功、数据库异常、平台有单但本地未找到、超出窗口、POS 已接收待过账、日志不可达、接口超时、无权限。必须能解释“无法判断”的原因。

默认只读，明确不包含真实补推、退货、京东税率、通用 SQL/Shell、全能自主 Agent。RAG 与受控补推分别作为第二、第三个可演示增量，避免把所有功能绑在首个 MVP。

## 阶段放行

设计审核后才开始阶段 3；阶段 0 的接口核验是对应真实适配器的前置条件。测试环境联调也需要提供明确的环境配置，禁止用生产凭证代替。每阶段评审关注测试证据、失败路径和新增未知项，验收失败先修复再扩场景。
