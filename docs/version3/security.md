# 远程日志权限与隐藏风险

## SELECT 不等于服务器只读

数据库账号的 SELECT 权限只约束数据库查询。SSH/SFTP 账号使用操作系统权限，二者应分别配置。Agent 自身只实现读取也不等于凭证在其他客户端中无法执行写入。

Linux 删除文件通常取决于父目录的写/执行权限，不能只把日志文件设成只读。账号若拥有日志目录，仍可能删除或重命名文件；如果还有 sudo、可写脚本、转发能力或其他登录入口，风险更大。

本方案采用多层限制：专用日志账号 + 禁止Shell的只读SFTP + chroot + 只读挂载 + 无目录/文件写权限 + 禁止转发。正确配置后，通过该 SFTP 入口发起删除、覆盖、重命名等请求会被拒绝；这不是对错误配置、服务器漏洞或管理员行为的绝对安全保证。

## 推荐部署关系

| 项目 | 配置 |
|---|---|
| 业务原目录 | `/data/service/b-push-center-server/logs` |
| 专用账号 | `retailops_logs`，无 sudo，不加入业务部署/容器等特权组 |
| chroot 根 | `/srv/retailops-log-jail`，所有祖先目录root所有且不可被普通用户写入 |
| chroot 内日志 | `/logs`，从业务原目录只读bind mount，不改业务进程现有写权限 |
| Agent 配置目录 | `/logs`，这是SFTP视图中的路径 |
| SSH认证 | 专用公钥；服务器root管理authorized_keys，客户端私钥由运行账号保护 |
| 主机校验 | 管理员通过独立可信渠道核对指纹后写入known_hosts；不自动接受首次连接 |
| 网络 | 只允许Agent主机访问该账号的SSH入口；根据网络实际情况再限制来源IP |

管理员参考 `config/ssh/sshd_config.example` 的 Match 配置，合并到实际配置并核验有效值。该文件不是完整sshd_config，不应覆盖现有配置。部署过程须保留现有管理员会话，使用服务器实际版本的 `sshd -t` 检查语法，以及 `sshd -T -C user=retailops_logs,host=...,addr=...` 检查匹配后的配置，再按企业流程加载。

`internal-sftp -R` 是服务端只读协议约束；`ChrootDirectory` 是可见目录约束；`DisableForwarding yes` 是转发约束。普通Unix目录ACL与只读挂载还需单独配置。主机现有OpenSSH版本是否支持这些项，需要管理员核验，不能静默忽略不支持项。

私钥默认使用受操作系统ACL保护的专用无交互密钥；当前适配器未实现带口令密钥的解锁入口。若企业要求口令密钥或密钥代理，应先扩展凭证提供接口，不把口令写进源码。主机密钥变更会拒绝连接，应重新核验，而非关闭校验。

## 仍然存在的风险与处理

| 风险 | 当前控制与局限 |
|---|---|
| 删除/覆盖服务器文件 | 客户端没有远程写操作；服务端只读SFTP及只读挂载必须实际配置。仅凭数据库SELECT无法保障 |
| 任意命令或命令注入 | 不开exec/shell频道，不拼接zcat/grep，不接受用户路径；固定目录、安全文件名和日期类型 |
| 查看其他订单和客户数据 | SFTP凭证本身可读授权挂载中的原始日志；应用只返回目标订单元数据。凭证失窃仍有泄露风险，应限制主机、目录、账号和密钥可读范围 |
| `grep -A 200` 混入其他订单 | 不原样返回窗口。每行独立验证身份，无法关联的邻行不作为证据，不传给模型 |
| 日志伪造或错误标记 | 日志是证据线索，不是不可篡改审计；接收标记须结合源码核验，任意字符串共现不能证明整个处理成功 |
| 文件轮转/符号链接竞态 | 普通文件与规范路径检查，读前后属性比较；父目录和挂载必须由可信管理员控制，应用检查不能完全消除竞态 |
| 压缩炸弹、磁盘/网络压力 | 压缩量、解压量、文件数、行长、并发、时间上限；Java侧解压减少服务器CPU压力，但仍消费生产服务器I/O和网络 |
| 超时与部分证据 | 断开SFTP会话并返回限制；不得把PARTIAL/UNAVAILABLE当作未接单 |
| 凭证进入Git或日志 | 本地配置和SSH密钥忽略提交，连接异常只返回安全码，不打印账号配置、原始日志或SDK签名 |

SFTP 方案会传输所扫描归档的压缩字节，较服务器端 grep 更消耗网络，但避免授予远程Shell并把解压CPU移到Agent侧。如果实际日志过大，后续可部署经鉴权的专用日志查询服务，在服务端按固定参数筛选；不应该通过放宽为任意SSH命令解决性能问题。

没有服务器访问资料，本次没有核验你的真实ACL、sshd有效配置或挂载，因此不能宣称现网已经具备这些限制。没有执行任何远程连接或权限修改。
