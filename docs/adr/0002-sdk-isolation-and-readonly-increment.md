# ADR-0002 首个真实接入增量与旧 SDK 隔离

日期：2026-11-09。状态：已实施第一阶段，用户实测待完成。

## 背景与决定

用户授权直接开发真实集成代码，禁止 Mock 和测试执行，并允许必要时降级至 Boot 3。当前 Boot 4.1.1 / Spring AI 2.0.2 的依赖解析和编译可继续，因此保持版本，不为了旧 SDK 自带依赖直接降级。

本地美团 SDK 为含大量附带类与服务描述的 JAR，直接加入主类路径会暴露旧 Fastjson、HTTP 客户端和注解处理器等。第一阶段将它作为外部运行资源，通过 URLClassLoader 与 Java 平台父加载器隔离；适配器用反射调用已静态核验的公开构造器/方法，跨边界仅传字符串。方法签名不匹配在启动阶段失败，不静默回退。

代价是依赖编译期类型检查被启动期方法校验替代，SDK 网络行为和连接资源仍需实测；这不是安全沙箱，也不证明旧库没有漏洞。SDK 查询只使用订单详情请求、固定 HTTPS 域名、显式签名模式与有限超时。

## 范围收敛

第一阶段实现 Spring AI 结构化意图、详情查询、门店授权、SQL Server 只读两表计数、确定性报告与本地任务记录。不将查无数据解释成可补推，不声明自动根因分析完成。

根据用户给出的 Mapper SQL，直接提供固定参数化 SELECT 适配器；没有生产数据库凭证，也没有执行任何 SELECT。动态数据源目前以管理员显式配置的 app_poi_code→数据库路由代替旧项目 AOP；映射表与流水表位置必须在部署配置时确认。跨库布局暂不猜测。

原设计的 HTTP 旧系统适配仍适用于后续正式补推入口；本阶段不重写财务/销售转换规则、不提供任意 SQL、不调用旧 test。无 Mock、不新增测试文件；构建跳过测试，用户手工验证思路见文档 18。

## 尚未交付

完整 Tool Calling、自主多步取证、日志搜索、RAG、生产审批与补推、分布式任务持久化、SSO 均未纳入这个增量。文件任务记录适用单实例，不可声称具备跨实例恢复或防篡改审计。后续以可验证的业务增量推进，不把计划写成完成成果。
