# 11 安全与权限

## 授权模型

使用 Spring Security；生产优先接企业 OIDC/SSO，服务端解析有效身份。Mock 仅用独立测试账号且绑定 mock profile。RBAC 定义动作，ABAC 定义租户/环境/平台/门店范围。

| 角色 | 允许行为 | 限制 |
|---|---|---|
| Viewer | 查询授权订单、报告 | 仅所属门店和平台 |
| Operator | 诊断、提交补推预检申请 | 不能审批自己的生产申请 |
| Approver | 审核范围内计划 | 不能修改已生成计划；权限和期限实时检查 |
| Auditor | 审计查看 | 不拥有执行权限，敏感证据按需授权 |
| IntegrationAdmin | 维护适配器与服务目录 | 不自动获得订单补推权限 |

没有通配“模型管理员”绕过业务权限。审批和执行都绑定具体 action、OrderKey、environment、planDigest 与有效期；“以后都同意”“帮我补推”不是后端无限授权。浏览器 Cookie 模式须考虑 CSRF，写接口拒绝 GET。用户撤权后已有计划也不能执行。

## 不可信输入与数据隔离

用户消息、日志、平台响应、RAG 文档和远端工具描述都不可信。防护包括结构化解析、长度限制、固定工具白名单、引用校验、网络允许列表、工具数据与指令分离。Prompt 中要求忽略注入只是辅助，真正边界在服务端。

不可提供任意 SQL、Shell、SSH、URL、文件读取工具。日志参数只用逻辑服务 ID；适配器禁用未经允许的重定向和目标地址变更，拒绝内部元数据地址及跨网络出口。即使模型生成合法工具名，也必须重新检查资源授权。

知识检索、任务状态、证据下载、缓存、导出与历史案例全部验证用户范围。缓存键包含租户、环境和授权范围版本；不能仅按 orderId 缓存。逐订单状态查询防 IDOR，管理员配置与业务查询接口分开。

## 密钥与模型出口

配置只存 secretRef，不把真实 Token 写在 application 文件、日志、报告或 Git 历史。开发用进程环境变量，部署使用企业秘密管理或受限挂载；限制证书与服务凭证权限并定期轮换。

调用 DeepSeek 前移除姓名、电话、地址、支付信息、签名与账号；订单号必要时使用任务内一致伪名。出网策略禁止时使用 Mock/内网模型，不能擅自把内容换发其他服务商。生产模型出口配置需企业批准，但本轮不申请凭证或访问真实数据。

## 副作用故障防线

必须先持久化计划、授权和审计意图再发送；审计存储不可用则关闭新写操作。网络发送后故障不能自动回滚外部事实，状态转 UNKNOWN。模型不能解除幂等占用、审批自己或把错误状态改成成功。任务取消不能承诺撤回已发生的远程写入。

## 验证门槛

跨门店、跨环境、直接调用执行 API、伪造审批、过期审批、参数更改、权限撤销、提示注入、路径穿越、SSRF、审计不可用均需测试。验收是测试集中越权执行数为 0，而不是宣称系统绝无漏洞。安全测试从基础阶段开始，不留到最后补做。
