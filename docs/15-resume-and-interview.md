# 15 简历与面试证据规划

完整的能力说明、美团销售订单逐步示例，以及不同实现阶段可使用的简历文案，见 [16-delivered-capabilities-and-resume.md](16-delivered-capabilities-and-resume.md)。本文保留评估证据和面试准备要求。

当前阶段只有设计，不能写“已上线”“提升 80%”“支撑万店”。简历必须区分个人原型、测试环境联调和真实企业上线，不能把平台原有业务代码成果全部归为新项目。

## 完成后可使用的描述结构

“设计并实现面向零售订单异常的 Java Agent 运维平台，采用 Spring AI、受控 Workflow 与分平台 HTTP 适配器，整合日志、本地订单及 POS 状态证据；以版本化 RAG 提供可追溯诊断，使用审批绑定、业务幂等和结果对账控制补推。”只有对应能力真实完成后才使用该表述。

量化模板：“在 N 条脱敏故障测试集、M 个场景中，根因 Macro-F1 为 X；与人工基线相比有效诊断耗时由 A 降至 B；在 C 类并发/故障注入测试中无重复业务创建。”所有字母需替换为可复现结果，并写明 Mock、测试或生产环境。

## 技术亮点与证据

| 亮点 | 要展示的实际材料 | 面试关键解释 |
|---|---|---|
| Agent 与确定性控制边界 | Prompt、Schema、Gateway 拒绝测试 | 模型可建议但不能决定权限和副作用 |
| 多系统证据诊断 | 实例覆盖、原始状态映射、报告引用 | 为什么没查到日志不等于没收到订单 |
| 持久化 Workflow | 状态记录、重启恢复测试 | 如何处理节点重复调度和外部不确定结果 |
| 受控自愈 | 审批摘要、幂等键、执行前后状态 | 为什么锁与数据库事务不能解决远程 exactly-once |
| RAG 工程 | 版本化知识、过滤、检索对比 | 实时工具和知识检索区别、中文检索与重排取舍 |
| Agent 评估 | 冻结集、模型版本、消融报告 | 如何避免数据泄漏及模型自评偏差 |
| 工程可观测性 | 一个 taskId 的 trace 与审计 | 为什么接口成功、POS 处理成功与过账不同 |

## 八分钟演示方案

1. 一分钟介绍美团销售真实业务链路和目前人工痛点。
2. 两分钟演示自然语言缺参追问、工具证据与日志覆盖。
3. 一分钟展示失败案例：平台窗口外或日志缺失，系统诚实输出未知。
4. 两分钟展示测试环境补推：预检、独立审批、并发重复拒绝、超时后对账。
5. 一分钟打开引用的 SOP 版本与故障 trace。
6. 一分钟展示评估集、消融结果及尚未覆盖的边界。

只完成只读 MVP 时把第 4 步标为后续设计，不录制伪造补推成功视频。

## 重点面试题

- 为何不直接让 LLM 调补推？说明权限不可由 Prompt 保证。
- 幂等键为何不能是随机 requestId？说明业务身份与请求尝试的区别。
- HTTP 超时但 POS 已写入怎么办？说明 UNKNOWN、核验与下游幂等前提。
- 五类流程为何不做五个 Agent？说明独立业务策略足够、并行 I/O 不等于多 Agent。
- 为何 Spring AI 而非同时引入 LangChain4j？说明现有 Spring 栈、依赖治理与评估取舍。
- RAG 如何防过期资料、越权召回和虚假引用？说明元数据过滤、版本与引用验证。
- 如何证明 AI 有收益？给出规则-only、固定取证、动态取证、RAG 的消融结果。

招聘能力补齐重点是 Python 数据处理/评估和 Agent 原理，不是为关键词堆框架。MCP、多 Agent、模型微调只在实际实现并能说明收益时写入简历。
