## 建议验收顺序

先在你的项目 JDK17 环境完成跳过测试的 package，再确认真实配置完整。随后由你选择已获授权、已知状态的订单进行只读验收。不要通过修改生产表、运行旧补推 test、断开生产数据库或制造异常来构造场景；没有既存样例的项保留待验收。

| 范围 | 输入/条件 | 预期观察 |
|---|---|---|
| 兼容 | 原有本地配置、不加diagnostics | 启动加载默认值；日志DISABLED、解释DISABLED、内置知识可用 |
| 原链路 | 既有两表均存在的授权订单 | outcome保持BOTH_FLOWS_PRESENT，K01适用，过账UNKNOWN |
| 单表 | 已有单表记录订单 | PARTIAL_FLOWS_PRESENT，K02适用；不补写 |
| 无流水 | 已知合法但当前两表为空 | NO_FLOWS_FOUND，K03适用；不认定漏推 |
| 查询失败 | 已存在的安全隔离配置错误记录/后续非生产环境 | POS_QUERY_FAILED，不能出现伪造零条count |
| 806/超窗 | 已知合法历史订单由用户自行只读请求 | 原有失败结论；details=null，无日志查询 |
| 日志正常 | 获准文本中同行有精确order/store | 仅返回别名、行号、哈希、类别，不回传原始日志 |
| 身份隔离 | 相近单号前后缀、不同门店、多身份同一行 | 不作为当前订单/门店证据 |
| 日志格式 | 仅订单号、无app_poi_code、跨行栈、压缩文件 | 不假定支持；未命中或跳过，不解释为未接单 |
| 资源上限 | 获准离线副本超出文件/字节/命中/时间限额 | PARTIAL及原因，不无限读取 |
| 异常文件 | 已有无效编码、超长行、未换行末行或不可读文件 | 对应局限码，其他可读证据可保留 |
| 文件变化 | 活跃日志自然追加/轮转 | 检测到变化标记FILE_CHANGED，不宣称快照完整 |
| 知识权限 | 私有条目限定门店A，查询获授权门店B | B报告/模型候选不可出现A条目 |
| 目录错误 | 本地无效JSON、重复ID、错误枚举或超限目录 | 启动失败，错误信息不包含文件正文或密钥 |
| 解释关闭 | explanation-enabled=false | 无二次调用，规则说明可读 |
| 解释开启 | 合法候选、可用模型 | MODEL_SELECTED，仅允许候选ID对应文字 |
| 模型失败/非法输出 | 后续由其他模型/开发者在隔离条件验证 | RULE_FALLBACK，不修改原outcome |
| 历史任务 | 旧V1文件 | details为空，仍按所有者/门店检查 |
| 引用撤回 | 本地目录变更或禁用后重启 | 对涉及旧引用的历史GET返回403；重新诊断生成新版本 |
| 越权 | 另一用户读taskId或查询未授权门店 | 403，无日志或知识越权披露 |
| 脚本 | 真实授权单号，输出至未存在路径 | 可保存JSON；不覆盖现有文件，不重定向发送Basic凭证 |

这里是验收设计，表中预期均不是已经通过的结果。
